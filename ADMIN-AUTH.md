# Administrator login

The dashboard signs in the platform administrator using email and password.
`POST /api/admin/login` accepts `{ "email": "admin@example.com", "password": "..." }`
and returns a `super_admin` JWT valid for eight hours. Email matching ignores case
and surrounding whitespace; passwords are compared exactly.

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD_HASH` in the server environment. Password
hashes use the versioned `scrypt-v1:<salt>:<hash>` format, generated by
`hashAdminPassword` in `server/src/modules/admin/admin-password.ts`. The Node.js
[scrypt implementation](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)
uses a random 16-byte salt with N=32768, r=8 and p=3. Keep credentials out of Git
and Docker images; `.env.admin` is excluded from both.

The local `.env.admin` contains the prepared administrator email and password hash.
For production, transfer that file privately alongside the existing `.env.prod`.
`deploy.sh` loads both files. To rebuild just the application services directly:

```sh
docker compose -f docker-compose.prod.yml --env-file .env.prod --env-file .env.admin up -d --build server web
```

Alternatively, set the two variables in the existing `.env.prod` and use the
normal deployment command. Other production settings are still required.
For local development, export both variables before starting the backend.

The login endpoint allows ten attempts per minute per server process, shared
across source IPs for this single administrator account. Multiple backend
processes require a shared limiter. Credential failures return the same message.

`ADMIN_API_KEY` remains available for direct API integrations. The dashboard no
longer accepts super-admin or tenant API keys as login credentials; this change
configures only the platform administrator account. Existing tenant JWTs remain
valid until they expire.
