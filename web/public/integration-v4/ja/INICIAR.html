サポート統合 · 契約 v4

SDK 0.3.0 · バックエンド、フロントエンド、運用マニュアル

1. 仕組み

バックエンドはユーザーを認証し、承認されたコンテキストを投影し、15分間のセッションを発行します。発行呼び出しでは、そのユーザーが利用できるMCPサーバーを含めることができます。ブラウザはウィジェットのJWTとコンテキストを受け取ります。

2. 環境と担当者

プラットフォームはhttps://support-ai.pontes.ukにあります。正しい環境の統合資格情報を使用してください。ワークスペース管理者は、パネルで資格情報を取得します。アプリケーションチームは、認証されたブートストラップ、コンテキスト、およびユーザーごと、サーバーごとの委任トークンを維持します。

3. 資格情報

資格情報 宛先 使用法
統合資格情報 sik_ Support AI バックエンドでセッションを発行する
サーバーごとの委任トークン セッションで示されるMCP 認証されたユーザーとしてツールを呼び出す
セッションのJWT チャットのAPI ウィジェットで会話を開いて続行する

統合資格情報をアプリケーションの金庫に保存します。それを失効させると、次のリクエストでそれによって発行されたJWTsが無効になります。バックエンドで委任トークンを生成し、それぞれを1つのリソース、ユーザー、および有効期限に制限します。

4. 認証とIDのフロー

アプリケーションの認証済みセッション
  → バックエンドはアクティブなユーザー、組織、現在の権限を検証します
  → サーバーでPOST /api/widget/sessionsとsik_
  ← jwt + tenantKey + expiresIn
  → バックエンドは同じIDのコンテキストを収集して投影します
  ← ブラウザはCache-Control: no-storeでセッション/コンテキストを受け取ります
  → ウィジェットは一時的なJWTで/api/casesと会話ルートを呼び出します

顧客の履歴識別子usr_...を保持することで、自分の会話へのアクセスを失うことを防ぎます。email、役割、デバイス、またはタイムスタンプをIDとして使用しないでください。同じユーザーが会社を変更できる場合、リンクまたは明示的な履歴ポリシーによって安定したサブジェクトを定義します。プラットフォームは、顧客の組織を推測することなく、テナント+ユーザーごとに会話を承認します。

プラットフォームは、署名、発行者ai-support、オーディエンスai-support-widget、目的widget、sub=userId、有効性、およびセッションのアクティブな資格情報を検証します。ブラウザはクレームを再署名したり変更したりしません。サポートに送信される役割はコンテキスト情報です。API/MCPの承認はクライアントサーバーで続行されます。

5. 発行者契約

POST https://support-ai.pontes.uk/api/widget/sessions
Authorization: Bearer <SUPPORT_INTEGRATION_CREDENTIAL>
Content-Type: application/json

{"userId":"usr_usuario_autenticado","userEmail":"","userRoles":["member"],"plan":"standard"}

応答200: {"jwt":"<JWT>","tenantKey":"ten_do_projeto","expiresIn":900}。ブラウザに返す前にtenantKeyを検証します。ファイルbackend-session.mjsは、厳密な本文、タイムアウト、リダイレクトのブロック、応答制限、テナントの検証を実装しています。これは認証ミドルウェアを置き換えるものではありません。

フィールド ルール
mcpServers id、URL、および一意のaccessTokenを持つ最大8つのオブジェクトのオプションリスト。セクション12を参照。
userId 必須、トリム、1〜200文字
userEmail 最大254文字の有効なメールアドレス、または空。デフォルトは空。
userRoles 1〜80文字の文字列を最大30個。デフォルトは空のリスト。
plan 1〜80文字の文字列。デフォルトはstandard。

tenantId、tenantKey、userName、role、purpose、exp、その他のフィールドを本文に送信しないでください。資格情報がテナントを決定します。IDはセッション/データベースから取得され、ブラウザのクエリ/本文からは取得されません。発行者は、ユーザーのJWT、管理キー、または古いシークレットをsik_の代わりとして受け入れません。

パブリック発行者は、プロジェクトごとの使用量クォータなしで動作します。同じ人物、会社、権限の有効なセッションを再利用し、変更時に早期期限切れと無効化を行います。

6. 必須のコンテキストと正しいID

新しいケースごとにcontext.userState、context.userHistory、context.userLogsが必要です。ソースがクエリされ、レコードがない場合は空のリストを送信します。失敗したコレクションを、成功したかのように見える空のリストに変換しないでください。有効で承認されたコンテキストを提供できない場合、クライアントのブートストラップは制御されたエラーを返す必要があります。

context.example.jsonは最小限の例です。context.schema.jsonは、サーバーで使用されているスキーマZodからエクスポートされたものであり、独立して作成されたものではありません。デプロイ前にバックエンドでJSONを検証してください。認識されない追加フィールドは破棄されます。メタデータとルールには独自の構造が含まれる場合があり、投影/制限の対象となります。スキーマは承認を証明するものではなく、すべての機密データを排除するものでもありません。

ブロック 必須 / 構造
userState userId, tenantId, roles, plan, featuresEnabled, entities, activeErrors, limitsReached
userHistory windowHoursは720まで正の値、events。タイムラインはeventsから再構築されます。
userLogs recentRequests, jobs, errors
knowledgePack オプション。id、title、content、categoryを含むdocs。
businessRules オプション。承認されたルールオブジェクト。ランブックとしてシリアル化されます。

userState.userIdは発行されたIDと完全に一致する必要があります。userState.tenantIdはプラットフォームのテナントであり、クライアントの組織/店舗IDではありません。不一致は403を返します。ブラウザのデータは改ざんされる可能性があります。コンテキストは操作を承認しません。

7. フィールド、制限、正規化

構造 主要フィールド / ルール
entities type、status。id/descriptionはオプション。metadataオブジェクト。最大100。
activeErrors errorCode、errorClass、retryable、userActionable、resourceId、occurredAt。最大100。
activeErrorsのerrorClass validation、permission、infra、またはbusiness。paymentのようなカテゴリはマッピングが必要です。
events ts、event、page、elementId、intent、correlationRequestId。nullまたは省略を受け入れます。最大1,000。
recentRequests ts、route、httpStatus整数、timingMs、requestId。errorCode/resourceIdはnullになることがあります。
jobs jobId、queue、status、createdAt、updatedAt、durationMs数値またはnull。errorCode/lastStageはnullになることがあります。
jobsのstatus queued, running, succeeded, failed, canceled
バックエンドのerrors ts、errorCode、errorClass文字列、route、requestId。resourceIdはnullになることがあります。
docs 最大50。contentは最大32,000文字、その他のテキストは最大4,096文字。

日付はタイムゾーン付きのISO-8601文字列です。バックエンドでDateをシリアル化してください。スキーマに合格するためだけにupdatedAt、durationMs、retryableやカテゴリを捏造しないでください。実際のソースを使用するか、レコードを省略してソースの利用不可を報告してください。プロジェクト固有のマッピングを承認時に記録してください。

送信されたコンテキストの天井: 262,144バイト UTF-8 (256 KiB)。完全な HTTP は1,048,576バイトに制限されたままです。スナップショットの予算は min(maxContextBytes, 262144) です。必須部分でさえ収まらない場合、リクエストは失敗します。バックエンドのメタデータ/ドキュメントを減らしてください。48 KiB、10エンティティ、短い知識から始めることをお勧めします。

サーバーは、要求されたウィンドウとテナントのウィンドウの小さい方でイベント/ログをフィルタリングし、将来の日付を削除し、リクエスト、エラー、および jobs (この順序) に結合された maxLogLines を適用します。 maxDocs は docs リストを制限します。 businessRules は別のランブックであり、総予算も消費します。タイムラインは保持されたイベントに従います。関連性の低いデータは、通常、より良い診断とより低いコストをもたらします。

8. プライバシーと永続性

送信前にデータを設計する: ヘッダー、Cookie、JWTs、資格情報、接続文字列、署名付きURL、バイナリコンテンツ、他のユーザーのデータ、または生のエクスポートを決して転送しないでください。秘密をサポート参照に置き換えます。知識ベースとして PRD 全体または完全なログを送信しないでください。

新しいスナップショットは、書き込み前に検証、編集、削減、予算編成が行われます。メッセージとツール結果は、既知の秘密パターン処理を受けます。この保護は補完的なものです。個人データの完璧な分類器ではなく、履歴レコードを遡及的に修正するものでも、顧客の設計に取って代わるものでもありません。

コンテキストは会話開始時のスナップショットであり、リアルタイムクエリではありません。タイムスタンプとソースを通知してください。 updateContext() は次のケースに適用されます。会話中の現在のデータについては、承認された読み取りツールを使用してください。

9. フロントエンドと SDK 0.3.0

パッケージまたは公開URLから固定された SDK を提供します。 SHA-256 を widget.manifest.json で確認します。重複したスクリプト、浮動バージョン、JWT のキャッシュを避けてください。 widget-controller.mjs の参照コントローラーは、ブートストラップ後にマウントされ、onOpen を待機し、更新し、ログアウト後の遅延マウントを防ぎます。

const controller = mountSupport({
  apiUrl: 'https://support-ai.pontes.uk',
  bootstrap: signal => fetchAuthenticatedBootstrap(signal),
  getContext: signal => fetchAuthorizedContext(signal),
  onUnavailable: () => showHumanSupportChannel(),
});
// ログアウト時、人物/会社/役割の変更時、コンポーネントのクリーンアップ時:
controller.destroy();

上記の関数はアプリケーションのコールバックであり、通常の HTTP クライアントで実装する必要があります。ブートストラップは {jwt,tenantKey,expiresIn,context} を返します。 getContext はコンテキストオブジェクトを返します。Reactでは、useCallback でコールバックを安定させ、IDにリンクされた useEffect でマウントします。ウィジェットを認証済みエリアの外に配置したり、共有 userId を持つ訪問者を提供したりしないでください。

SDK は、新しい JWT を返す onTokenRefresh を受け入れます。401の後、リクエストを一度繰り返します。更新は同じ人物を使用する必要があります。IDの変更には、破棄と初期化が必要です。プロアクティブなタイマーを使用する場合は、ジッターを伴う約10分を好み、クリーンアップ時にキャンセルしてください。ブートストラップ、収集、モデルのエラーは、メインアプリケーションをブロックしてはなりません。

10. ログアウト、権限、履歴

destroy() は呼び出しを中止し、テナント/個人ごとにローカルの永続性を削除します。これはサーバー上での個別の取り消しではありません。すでにコピーされた JWT は、クライアントでのログアウト/ロック後、最大15分間有効なままになることがあります。個人ごとの即時取り消しが必要な場合、契約には追加の進化が必要です。テナント全体のローテーションを通常のログアウトとして使用しないでください。

各会話の読み取り/書き込みには、同じ所有者とテナントが必要です。クライアントでの役割変更は、その人が会話ですでに受け取ったコンテンツを消去しません。権限の降格や組織変更のために履歴ポリシーを定義してください。古い caseId を回復するために承認を緩和しないでください。元のサブジェクトを確認するか、新しい会話を開始してください。

11. CORS、CSP、PWA、およびアクセス

各フロントエンドの正確なオリジンをプラットフォームで許可します。SDK はサポートのために connect-src を必要とします。ローカルファイルを配信すると script-src が自己許可されます。SDK は Shadow DOM にスタイルを挿入し、まだ nonce を受け取っていません。実際の CSP ポリシーを承認し、外部スタイル/nonce/ハッシュのために SDK の進化が必要になる場合があります。ポリシー全体をオフにしないでください。

セッションとコンテキストは no-store です。PWA のキャッシュ、クエリの永続性、リプレイツールからサポートルートを除外します。キーボード、フォーカス、スクリーンリーダー、ズーム、モバイルをテストします。確認済みの時間/URLとともに、アプリ内で真の人間チャネルを提示します。SDK はサービスプロバイダーを発明しません。

12. セッション内の MCP サーバー

アプリケーションのバックエンドは、統合資格情報 sik_ を使用して POST /api/widget/sessions を送信します。これにより、ログインから個人とその組織が派生し、mcpServers に最大8つのサーバーを含めることができます。省略または空のフィールドは、コンテキストを持つチャットを作成します。新しいセッションごとに独自のリストが受信されます。

{
  "userId": "usr_ana",
  "mcpServers": [
    {"id":"billing","url":"https://billing.example/mcp","accessToken":"TOKEN_DELEGADO_BILLING"},
    {"id":"crm","url":"https://crm.example/mcp","accessToken":"TOKEN_DELEGADO_CRM"}
  ]
}

各 id は小文字で始まり、小文字、数字、アンダースコア、ハイフンを受け入れ、最大32文字です。ID、正規化されたURL、トークンはリスト内で一意です。トランスポートはパブリック HTTPS のポート443で MCP Streamable HTTP であり、資格情報、クエリ、またはフラグメントのないURLを使用します。サービスは接続時に DNS を検証し、リダイレクトを拒否します。

アプリケーションは、その MCP の個人、組織、権限、およびオーディエンスに制限された、各宛先への短いアクセストークンを発行または取得します。Support AI は対応するサーバーに Authorization: Bearer <accessToken> を提示します。プロバイダーは、各操作で署名またはイントロスペクション、発行者、有効性、オーディエンス、およびリソースへのアクセスを検証します。そのIDに許可されたツールのみをカタログに公開します。プラットフォームの資格情報、ウィジェットの JWT、および Stripe などのサービスキーには独自の目的があります。

委任されたトークンは、サーバー上で最大900秒間暗号化されたままになります。ブラウザは {jwt, tenantKey, expiresIn: 900} を受け取ります。更新時、バックエンドはIDを再検証し、有効なトークンを含む新しいリストを送信します。更新前に作成された提案は、再度提示する必要があります。組織変更の場合、リンクごとに安定した識別子を使用し、ウィジェットの以前のインスタンスを破棄します。

Support AI は tools/list のページを巡回し、サーバーごとに同じ名前を区別し、tools/call を呼び出す際に元の名前を使用します。32 を超えるツールを持つカタログには、チャット内で検索とページネーションがあります。サーバーごとの検出制限は 128 ページと 4 MB の説明です。サーバーの検出に失敗しても、他のサーバーは維持されます。

annotations.readOnlyHint: true を持つツールは直接照会できます。アノテーションがないか偽であるすべてのツールについて、チャットは実行前にサーバー、名前、引数を表示します。ビジネス効果のない操作には読み取り専用を宣言してください。ユーザーは表示されたメッセージに 5 分以内に confirmar または confirm で応答します。SDK は replyToMessageId を送信します。確認は、それらの引数、サーバー、セッション、および会話に対して有効です。新しい提案は以前の提案を置き換えます。

プラットフォームは確認を登録した後、実行を試行し、提案の ID とともに Idempotency-Key を送信します。支払いおよび外部効果を伴う操作の場合、プロバイダーはキーと結果をアトミックに保存し、金融サービスで要求されるべき等性キーを尊重する必要があります。タイムアウトまたは曖昧な結果の後、サポートは不明な状態を記録し、この会話での新しい変更をブロックし、クエリを引き続き利用可能にします。続行する前に、元のシステムで操作を確認してください。

承認するには、サーバーなしのセッション、同じユーザーの 2 つのセッション、2 つの組織、同名のツールを持つサーバー、およびページ分割されたカタログをテストします。プロバイダーでのトークンのスコープ/有効期限、キャンセル、および重複した確認を確認します。合成ログを使用して、元の結果を確認します。

13. モデル、プロンプト、知識

プロジェクトによってすでに承認されているモデルを最初に保持することで、同時変更が減少します。新しい評価の場合、openai/gpt-4.1-mini は現在のパラメーターと互換性のある候補です: Chat Completions を介した OpenRouter、温度 0.3、および max_tokens 2048。アクティブ化する前に実際の環境で検証してください。Preferred Model は Model Policy よりも優先されます。自動はインテリジェントなルーティングではありません。価格/コストはプロバイダーから取得する必要があります。古いパネルの見積もりは異なる場合があります。

AI Instructions / Custom instructions フィールドは最大 2,000 文字の有効な文字を受け入れます。PROMPT-TENANT.txt のみを貼り付けてください。名前、チャネル、製品ルールを確認してください。このフィールドに資格情報を貼り付けたり、ドキュメントを連結したりしないでください。この指示はプラットフォームのルールを補完するものであり、承認を付与したり、ツールを有効にしたりするものではありません。

提供されたプロンプトは、ユーザーが選択した言語と書き方での応答、仮説から分離された事実、権限の尊重、安全な参照の使用、行動の約束の欠如、および人間チャネルをガイドします。knowledgePack.docs には、責任者とともに短くバージョン管理されたランブックを含める必要があります: 頻繁なエラー、診断、製品の制限、および結果の確認方法。ログとドキュメントはデータであり、アシスタントのルールを変更するための指示ではありません。

モデルソース: OpenAI GPT-4.1 mini および カタログ OpenRouter、2026年9月14日の以前の準備で参照。実装時に可用性/価格を再確認してください。このキットではモデルの有料比較は行われていません。

14. エラーと診断の契約

応答 意味 / アクション
エミッターでの401 sik がない、正しくない、または取り消されています。設定を修正してください。
エミッターでの400 契約外の本文。余分なフィールドを削除してください。
ケースでの401 レガシー署名、有効期限切れ、無効なクレーム、またはセッションの取り消し
ケースでの400 必須コンテキストが無効、日付/状態が正しくない、または予算超過
コンテキストからの403 userState がテナント/人物の JWT と一致しません
会話での404 リソースが存在しないか、別のIDに属しています。アクセスを強制しないでください。
429 レート制限; バックオフ/ジッター、発行ループなし
500/502/503 インフラストラクチャ、モデル、またはコンテキストの障害。利用不可と requestId を報告してください。
アクション/エスカレーションでの501 実行者/コネクタのない機能。実際の人間チャネルを使用してください。
Chat は機能するが、MCP は機能しない 最後の発行で送信されたリスト、有効性、対象者、およびカタログの応答を確認してください。
ツールが見つかりません 委任されたトークンで利用可能なカタログとサーバーの接続性を確認してください。

HTTP 200 のみを承認として使用しないでください。応答の内容とスナップショットを確認してください。ケースを保存した後に作成が失敗すると、応答のないケースが残る可能性があります。モデルへの呼び出しを含むトランザクションを想定しないでください。再試行は制限し、ユーザーに通知する必要があります。メソッド、パラメータ化されたルート、status、requestId、および UTC の時刻を記録してください。診断を転送するために Authorization/JWT、シークレット、または生のペイロードをキャプチャしないでください。

15. 必須の承認

  1. ログインなしのブートストラップルートは、エミッターの前に拒否されます。偽造されたIDは、認証されたユーザーを変更しません。
  2. 正しい資格情報での発行は、期待されるテナントと900秒を返します。シークレットはブラウザ/リプレイ/ログには表示されません。
  3. 古い JWT は拒否されます。新しいセッションは、スナップショットと実際の応答で会話を作成します。同じ人物のために再開します。
  4. 同じプロジェクトの2人の人物と2つのテナント: GET ケースと POST メッセージ/フィードバック/クローズ/エスカレート/アクションはIDを交差させません。
  5. ブロックなしのコンテキスト、異なるID、無効な日付、および過剰なサイズは拒否されます。合成シークレットはスナップショットに保持されません。
  6. 15分後の更新、収集中のログアウト、アカウント/会社/役割の変更、およびナビゲーションは、他の人の会話を復元しません。
  7. モデルは証拠を使用して応答し、診断の制限を尊重します。失敗は明らかな成功を生成しません。
  8. ゼロと2つのサーバーでセッションを発行します。各宛先が独自のトークンを受け取ることを確認してください。
  9. MCP は、間違った/古いトークン、間違ったテナント、ユーザーの欠落/非アクティブ、および他の人のリソースを拒否します。セッションがある場合は、再利用されたセッションIDをテストしてください。
  10. 変更には提案の確認が必要であり、タイムアウトの場合に繰り返されないことを確認してください。
  11. CORS/CSP、携帯電話、キーボード、および人間チャネルが承認されています。調整されたローテーションは承認でテストされています。

node --test examples.test.mjs は、モックを使用して分離されたアダプターを検証します。これらのエンドツーエンドテストを置き換えるものではありません。ACEITE.md に担当者、バージョン、時刻、および機密情報を含まない証拠を記入してください。

16. 公開、カット、および復元

統合クレデンシャルをインストールし、ブートストラップと SDK を公開し、チャットを検証し、セッションで宣言されたサーバーを承認します。

レガシーサブスクリプションやグローバル MCP 転送を再アクティブ化して可用性を回復しないでください。障害が発生した場合は、影響を受けるテナントのウィジェットまたは MCP を一時的に無効にし、アダプターを修正する間、人間チャネルを維持してください。所有者の 404 を回避するために会話を削除しないでください。

保持制限とアプリケーション固有の証拠を記録してください。

17. フィードバックとパッケージファイル

プロジェクト名、テナント、バックエンド/フロントエンドコミット、UTC 日付、SDK/ハッシュ、インストールされたクレデンシャル（はい/いいえ、値なし）、承認されたチャット、承認/無効化された MCP、ネガティブテスト、人間チャネル、および未解決の項目を返します。「動作するようです」で締めくくらないでください。

公開キットには、Markdown 形式のこのガイド、サーバーのスキーマ、最小限のフィクスチャ、発行元アダプター、MCP 認証、フロントエンドコントローラー、SDK、プロンプト、分離テスト、チェックリスト、アクション契約、および SHA-256 マニフェストが含まれています。個々のパッケージには、特定の添付ファイルが追加される場合があります。例では、クライアントアプリケーションのエンドポイントは自動的に実装されません。閲覧可能なバージョンは https://support-ai.pontes.uk/developers?lang=ja にあります。
