## 1. Как это работает

Ваш бэкенд аутентифицирует пользователя, проецирует авторизованный контекст и выдает 15-минутную сессию. При вызове выдачи он может включать доступные серверы MCP для этого человека. Браузер получает JWT виджета и контекст.

## 2. Среды и ответственные

Платформа находится по адресу https://support-ai.pontes.uk. Используйте учетные данные для интеграции из правильной среды. Администратор рабочей области получает учетные данные на панели управления. Команда приложения поддерживает аутентифицированный bootstrap, контекст и делегированные токены для каждого пользователя и сервера.

## 3. Учетные данные

| Учетные данные | Назначение | Использование |
| --- | --- | --- |
| Учетные данные для интеграции sik_ | Support AI | Выдача сессии на бэкенде |
| Делегированный токен для каждого сервера | MCP, указанный в сессии | Вызов инструментов как аутентифицированный пользователь |
| JWT сессии | API чата | Открытие и продолжение разговоров в виджете |

Храните учетные данные для интеграции в хранилище приложения. Отзыв этих учетных данных деактивирует JWTs, выданные с их помощью, при следующем запросе. Генерируйте делегированные токены на бэкенде и ограничивайте каждый ресурс, пользователя и срок действия.

## 4. Поток аутентификации и идентификации

```text
Аутентифицированная сессия приложения
  → бэкенд проверяет активного пользователя, организацию и текущие разрешения
  → POST /api/widget/sessions с sik_ на сервере
  ← jwt + tenantKey + expiresIn
  → бэкенд собирает и проецирует контекст ТОЙ ЖЕ личности
  ← браузер получает сессию/контекст с Cache-Control: no-store
  → виджет вызывает /api/cases и маршруты разговора с временным JWT
```

Сохранение исторического идентификатора клиента `usr_...` позволяет избежать потери доступа к собственным разговорам. Не используйте email, роль, устройство или временную метку в качестве идентификатора. Если один и тот же пользователь может менять компанию, определите стабильный субъект по связи или явной политике истории; платформа авторизует разговоры по арендатору + человеку, не выводя организации клиента.

Платформа проверяет подпись, издателя `ai-support`, аудиторию `ai-support-widget`, назначение `widget`, `sub=userId`, срок действия и активные учетные данные сессии. Браузер не переподписывает и не изменяет утверждения. Роли, отправленные в службу поддержки, являются контекстной информацией; авторизация API/MCP продолжается на клиентском сервере.

## 5. Контракт эмитента

```http
POST https://support-ai.pontes.uk/api/widget/sessions
Authorization: Bearer <SUPPORT_INTEGRATION_CREDENTIAL>
Content-Type: application/json

{"userId":"usr_usuario_autenticado","userEmail":"","userRoles":["member"],"plan":"standard"}
```

Ответ 200: `{"jwt":"<JWT>","tenantKey":"ten_do_projeto","expiresIn":900}`. Проверьте `tenantKey` перед возвратом в браузер. Файл `backend-session.mjs` реализует строгий тело запроса, таймаут, блокировку перенаправлений, ограничение ответа и проверку арендатора; он не заменяет ваш промежуточный слой аутентификации.

| Поле | Правило |
| --- | --- |
| mcpServers | Необязательный список до восьми объектов с уникальными id, url и accessToken. См. раздел 12. |
| userId | Обязательно, без пробелов, 1–200 символов |
| userEmail | Действительный адрес электронной почты до 254 символов или пустой; по умолчанию пустой |
| userRoles | До 30 строк по 1–80 символов; по умолчанию пустой список |
| plan | Строка 1–80 символов; по умолчанию standard |

Не отправляйте tenantId, tenantKey, userName, role, purpose, exp или другие поля в теле запроса. Учетные данные определяют арендатора. Идентификация происходит из сессии/базы данных, а не из запроса/тела браузера. Эмитент не принимает JWT пользователя, административный ключ или старый секрет вместо `sik_`.

Публичный эмитент работает без квот использования на проект. Повторно используйте все еще действительную сессию одного и того же лица, компании и разрешений, с досрочным истечением срока действия и аннулированием при изменениях.

## 6. Обязательный контекст и правильная идентификация

Каждый новый случай требует `context.userState`, `context.userHistory` и `context.userLogs`. Отправляйте пустые списки, если источник был запрошен и записей нет; **не преобразуйте неудачный сбор в пустой список, который выглядит успешным**. Если вы не можете предоставить действительный и авторизованный контекст, клиентский bootstrap должен вернуть контролируемую ошибку.

`context.example.json` — это минимальный пример. `context.schema.json` был экспортирован из схемы Zod, используемой на сервере, а не написан независимо. Проверьте JSON на бэкенде перед развертыванием. Нераспознанные дополнительные поля отбрасываются; метаданные и правила могут содержать собственные структуры, подлежащие проекции/ограничениям. Схема не подтверждает авторизацию и не исключает все конфиденциальные данные.

| Блок | Обязательно / структура |
| --- | --- |
| userState | userId, tenantId, roles, plan, featuresEnabled, entities, activeErrors, limitsReached |
| userHistory | windowHours положительное до 720, events; временная шкала восстанавливается из events |
| userLogs | recentRequests, jobs, errors |
| knowledgePack | Необязательно; docs с id, title, content, category |
| businessRules | Необязательно; утвержденный объект правил, сериализованный как runbook |

`userState.userId` должен быть точно таким же, как выданный идентификатор. **`userState.tenantId` — это арендатор платформы**, а не идентификатор организации/магазина у клиента. Расхождения возвращают 403. Данные в браузере могут быть подделаны; контекст не авторизует операции.

## 7. Поля, ограничения и нормализация

| Структура | Основные поля / правила |
| --- | --- |
| entities | type, status; id/description необязательно; metadata объект; до 100 |
| activeErrors | errorCode, errorClass, retryable, userActionable, resourceId, occurredAt; до 100 |
| errorClass из activeErrors | validation, permission, infra или business; категории, такие как payment, требуют сопоставления |
| events | ts, event, page; elementId, intent, correlationRequestId принимают null/опущение; до 1000 |
| recentRequests | ts, route, httpStatus целое число, timingMs, requestId; errorCode/resourceId могут быть null |
| jobs | jobId, queue, status, createdAt, updatedAt, durationMs число или null; errorCode/lastStage могут быть null |
| status из jobs | queued, running, succeeded, failed, canceled |
| errors из бэкенда | ts, errorCode, errorClass строка, route, requestId; resourceId может быть null |
| docs | До 50; content до 32 000 символов, остальные тексты до 4096 |

Даты — это строки ISO-8601 с часовым поясом; сериализуйте Date на бэкенде. Не изобретайте updatedAt, durationMs, retryable или категории только для прохождения схемы: используйте реальный источник или опустите запись и сообщите о недоступности источника. Зарегистрируйте специфические для вашего проекта сопоставления в акцепте.

Отправленный контекст: **262 144 байта UTF-8 (256 KiB)**. Полный HTTP по-прежнему ограничен 1 048 576 байтами. Бюджет снимка составляет `min(maxContextBytes, 262144)`. Если даже основная часть не помещается, запрос завершается с ошибкой; уменьшите метаданные/документы в бэкенде. Мы предлагаем начать с 48 KiB, десяти сущностей и коротких знаний.

Сервер фильтрует события/журналы по наименьшему окну между запрошенным и окном клиента, удаляет будущие даты и применяет maxLogLines в сочетании с запросами, ошибками и jobs (в этом порядке). maxDocs ограничивает список docs; businessRules — это отдельный runbook, который также занимает весь бюджет. Временная шкала следует за сохраненными событиями. Меньшее количество релевантных данных обычно приводит к лучшей диагностике и меньшим затратам.

## 8. Конфиденциальность и постоянство

Проектируйте данные перед отправкой: никогда не пересылайте заголовки, файлы cookie, JWTs, учетные данные, строки подключения, подписанные URL-адреса, двоичный контент, данные других пользователей или необработанные экспорты. Заменяйте секреты ссылками на поддержку. Не отправляйте весь PRD или полные журналы в качестве базы знаний.

Новые снимки проходят проверку, редактирование, сокращение и бюджетирование перед записью. Сообщения и результаты инструментов обрабатываются с учетом известных шаблонов секретов. Эта защита является дополнительной: она не является безошибочным классификатором персональных данных, не исправляет исторические записи задним числом и не заменяет проектирование клиентом.

Контекст — это снимок начала разговора, а не запрос в реальном времени. Указывайте временные метки и источники. `updateContext()` действует для следующего случая; для текущих данных во время разговора используйте утвержденный инструмент чтения.

## 9. Фронтенд и SDK 0.3.0

Обслуживайте SDK, зафиксированный в пакете или по общедоступному URL-адресу. Проверьте SHA-256 с `widget.manifest.json`. Избегайте дублирования скриптов, плавающих версий и кэширования JWT. Эталонный контроллер в `widget-controller.mjs` монтируется после загрузки, ожидает onOpen, обновляется и предотвращает позднюю монтировку после выхода из системы.

```js
const controller = mountSupport({
  apiUrl: 'https://support-ai.pontes.uk',
  bootstrap: signal => fetchAuthenticatedBootstrap(signal),
  getContext: signal => fetchAuthorizedContext(signal),
  onUnavailable: () => showHumanSupportChannel(),
});
// При выходе из системы, смене пользователя/компании/роли и очистке компонента:
controller.destroy();
```

Вышеуказанные функции являются обратными вызовами приложения, которые должны быть реализованы с вашим обычным клиентом HTTP. Bootstrap возвращает `{jwt,tenantKey,expiresIn,context}`. getContext возвращает объект контекста. В React стабилизируйте обратные вызовы с помощью useCallback и монтируйте в useEffect, связанном с идентификатором. Не размещайте виджет за пределами аутентифицированной области и не предлагайте посетителям общий userId.

SDK принимает `onTokenRefresh`, который возвращает новый JWT; после 401 повторяет запрос один раз. Обновление должно использовать того же человека. Изменение идентификатора требует уничтожения и инициализации. Если используется проактивный таймер, предпочтительно около десяти минут с джиттером и отмена при очистке. Ошибки загрузки, сбора и модели не должны блокировать основное приложение.

## 10. Выход из системы, разрешения и история

`destroy()` aborta chamadas e remove persistência local por tenant/pessoa. Não é revogação individual no servidor. Um JWT já copiado pode permanecer válido por até 15 minutos após logout/bloqueio no cliente. Se precisar de revogação imediata por pessoa, o contrato requer evolução adicional; não usar rotação de todo o tenant como logout normal.

Cada leitura/escrita de conversa exige o mesmo proprietário e tenant. Mudança de papel no cliente não apaga conteúdo que a pessoa já recebeu na conversa. Definir política de histórico para rebaixamento de permissões e mudanças de organização. Não relaxar autorização para recuperar um caseId antigo; verificar o subject original ou iniciar nova conversa.

## 11. CORS, CSP, PWA e acesso

Permitir na plataforma a origem exata de cada frontend. O SDK precisa de connect-src para o suporte; servir o arquivo local permite script-src self. O SDK injeta estilo no Shadow DOM e ainda não recebe nonce: homologar a política CSP real, podendo exigir evolução do SDK para estilos externos/nonce/hash. Não desligar a política inteira.

Sessões e contexto são no-store. Excluir rotas de suporte dos caches da PWA, persistência de queries e ferramentas de replay. Testar teclado, foco, leitor de tela, zoom e celular. Apresentar canal humano verdadeiro no aplicativo, com horário/URL confirmados. O SDK não inventa um provedor de atendimento.

## 12. Servidores MCP na sessão

O backend do aplicativo envia `POST /api/widget/sessions` com a credencial de integração `sik_`. Ele deriva a pessoa e sua organização do login e pode incluir até oito servidores em `mcpServers`. O campo omitido ou vazio cria um chat com contexto. Cada nova sessão recebe sua própria lista.

```json
{
  "userId": "usr_ana",
  "mcpServers": [
    {"id":"billing","url":"https://billing.example/mcp","accessToken":"TOKEN_DELEGADO_BILLING"},
    {"id":"crm","url":"https://crm.example/mcp","accessToken":"TOKEN_DELEGADO_CRM"}
  ]
}
```

Cada id começa com uma letra minúscula e aceita letras minúsculas, dígitos, sublinhado e hífen, até 32 caracteres. IDs, URLs normalizadas e tokens são exclusivos na lista. O transporte é MCP Streamable HTTP em HTTPS público, porta 443, com URL sem credenciais, query ou fragmento. O serviço verifica o DNS ao conectar e rejeita redirecionamentos.

O aplicativo emite ou obtém um token de acesso curto para cada destino, restrito à pessoa, organização, permissões e audiência daquele MCP. O Support AI apresenta `Authorization: Bearer <accessToken>` ao servidor correspondente. O provedor verifica assinatura ou introspecção, emissor, validade, audiência e acesso ao recurso em cada operação. Ele publica no catálogo somente as ferramentas permitidas para essa identidade. A credencial da plataforma, o JWT do widget e as chaves de serviços como Stripe têm finalidades próprias.

O token delegado fica cifrado no servidor por até 900 segundos. O navegador recebe `{jwt, tenantKey, expiresIn: 900}`. Ao renovar, o backend revalida a identidade e envia uma nova lista com tokens válidos. Uma proposta criada antes da renovação precisa ser apresentada novamente. Para mudança de organização, use um identificador estável por vínculo e destrua a instância anterior do widget.

Support AI просматривает страницы `tools/list`, различает одинаковые имена по серверу и использует исходное имя при вызове `tools/call`. Каталоги с более чем 32 инструментами имеют поиск и пагинацию в чате. Лимиты обнаружения на сервер составляют 128 страниц и 4 МБ описаний. Сбой обнаружения одного сервера сохраняет остальные.

Инструменты с `annotations.readOnlyHint: true` можно запрашивать напрямую. Для каждого инструмента с отсутствующей или ложной аннотацией чат показывает сервер, имя и аргументы перед выполнением. Объявляйте только чтение для операций без бизнес-эффектов. Пользователь отвечает `confirmar` или `confirm` на отображаемое сообщение в течение пяти минут. SDK отправляет `replyToMessageId`. Подтверждение действительно для этих аргументов, сервера, сессии и разговора. Новое предложение заменяет предыдущее.

Платформа делает попытку выполнения после регистрации подтверждения и отправляет `Idempotency-Key` с ID предложения. Для платежей и операций с внешними эффектами провайдер должен атомарно сохранять ключ и результат и соблюдать ключи идемпотентности, требуемые финансовой службой. После таймаута или неоднозначного результата поддержка регистрирует неизвестное состояние, блокирует новые изменения в этом разговоре и сохраняет доступные запросы. Проверьте операцию в исходной системе перед продолжением.

Для аттестации протестируйте сессию без серверов, две сессии одного пользователя, две организации, серверы с одноименными инструментами и каталоги с пагинацией. Проверьте область действия/срок действия токенов у провайдера, отмену и дублирование подтверждения. Используйте синтетические записи для проверки результата в источнике.

## 13. Модель, промпт и знания

Сохранение уже утвержденной проектом модели изначально уменьшает одновременные изменения. Для новой оценки `openai/gpt-4.1-mini` является совместимым кандидатом с текущими параметрами: Chat Completions через OpenRouter, температура 0.3 и max_tokens 2048. Проверьте на реальном аккаунте перед активацией. Preferred Model имеет приоритет над Model Policy; auto не является интеллектуальной маршрутизацией. Цены/стоимость должны поступать от провайдера; старые оценки на панели могут отличаться.

Поле **AI Instructions / Custom instructions** принимает до 2000 эффективных символов. Вставляйте только `PROMPT-TENANT.txt`; проверьте имена, канал и правила продукта. Не вставляйте учетные данные и не объединяйте документы в этом поле. Инструкция дополняет правила платформы; она не предоставляет авторизацию и не включает инструменты.

Предоставленный промпт направляет ответы на выбранном пользователем языке и в выбранном стиле, отделяет факты от гипотез, соблюдает разрешения, использует надежные ссылки, не обещает действий и использует человеческий канал. `knowledgePack.docs` должен содержать короткие, версионированные руководства с указанием ответственного: частые ошибки, диагностика, ограничения продукта и как подтвердить результат. Журналы и документы — это данные, а не инструкции по изменению правил помощника.

Источники моделей: [OpenAI GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) и [каталог OpenRouter](https://openrouter.ai/api/v1/models), просмотренные при предварительной подготовке 14.09.2026. Повторно подтвердите доступность/цены при внедрении; в этом комплекте не было платного сравнения моделей.

## 14. Контракт об ошибках и диагностике

| Ответ | Значение / действие |
| --- | --- |
| 401 в эмитенте | sik отсутствует, неверный или отозван; исправьте конфигурацию |
| 400 в эмитенте | Тело вне контракта; удалите лишние поля |
| 401 в случаях | Устаревшая подпись, истечение срока действия, недействительные утверждения или отозванная сессия |
| 400 в случаях | Недействительный обязательный контекст, неверные даты/состояния или превышен бюджет |
| 403 из контекста | userState не соответствует арендатору/лицу JWT |
| 404 в разговоре | Несуществующий ресурс или принадлежащий другой личности; не принуждайте к доступу |
| 429 | Лимит; откат/джиттер, без цикла выдачи |
| 500/502/503 | Сбой инфраструктуры, модели или контекста; сообщите о недоступности и requestId |
| 501 в действиях/эскалации | Функциональность без исполнителя/коннектора; используйте реальный человеческий канал |
| Chat работает, MCP нет | Проверьте список, отправленный в последней выдаче, срок действия, аудиторию и ответ каталога. |
| Инструмент отсутствует | Проверьте доступный каталог для делегированного токена и подключение к серверу. |

Не используйте только HTTP 200 как подтверждение: проверьте содержимое ответа и снимок. Создание, которое завершается сбоем после сохранения случая, может оставить случай без ответа; не предполагайте транзакцию, включающую вызов модели. Повторные попытки должны быть ограничены и сообщены пользователю. Зарегистрируйте метод, параметризованный маршрут, status, requestId и время UTC; никогда не захватывайте Authorization/JWT, секрет или необработанную полезную нагрузку для пересылки диагностики.

## 15. Обязательное подтверждение

1. Маршрут начальной загрузки без входа отклонен до эмитента. Поддельные идентификаторы не меняют аутентифицированного пользователя.
2. Выдача с правильными учетными данными возвращает ожидаемого арендатора и 900 секунд; секрет не отображается в браузере/повторе/журналах.
3. Старый JWT отклоняется. Новая сессия создает разговор со снимком и реальным ответом; повторно открывается для того же человека.
4. Два человека из одного проекта и два арендатора: GET case и POST messages/feedback/close/escalate/actions не пересекают идентификаторы.
5. Контекст без блоков, другая личность, неверная дата и избыточный размер отклоняются; синтетические секреты не сохраняются в снимке.
6. Продление через 15 минут, выход из системы во время сбора, смена учетной записи/компании/роли и навигация не восстанавливают разговор другого человека.
7. Модель отвечает, используя доказательства, и соблюдает лимит диагностики; сбой не приводит к видимому успеху.
8. Выдайте сессии с нулем и двумя серверами. Убедитесь, что каждый пункт назначения получает свой собственный токен.
9. MCP отклоняет неверный/старый токен, неверного арендатора, отсутствующего/неактивного пользователя и ресурс другого человека. Проверьте повторно используемый идентификатор сессии, если сессия существует.
10. Подтвердите, что изменения требуют подтверждения предложения и не повторяются в случае тайм-аута.
11. CORS/CSP, мобильный телефон, клавиатура и человеческий канал одобрены. Скоординированная ротация протестирована в процессе утверждения.

`node --test examples.test.mjs` проверяет изолированные адаптеры с помощью моков. Это не заменяет сквозные тесты. Заполните `ACEITE.md` ответственными лицами, версиями, временем и неопубликованными доказательствами.

## 16. Публикация, вырезка и восстановление

Установите учетные данные для интеграции, опубликуйте начальный загрузчик и SDK, проверьте чат и утвердите серверы, объявленные в сеансах.

Не реактивируйте устаревшие подписки или глобальную пересылку MCP для восстановления доступности. В случае сбоя временно отключите виджет или MCP затронутого клиента и поддерживайте человеческий канал, пока адаптер исправляется. Не удаляйте разговоры, чтобы обойти ошибку 404 владельца.

Запишите лимиты хранения и конкретные доказательства вашего приложения.
