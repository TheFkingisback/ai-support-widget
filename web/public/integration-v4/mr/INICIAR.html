समर्थन एकत्रीकरण · करार v4

SDK 0.3.0 · बॅकएंड, फ्रंटएंड आणि ऑपरेशन मॅन्युअल

1. ते कसे कार्य करते

तुमचा बॅकएंड वापरकर्त्याची पडताळणी करतो, अधिकृत संदर्भ प्रोजेक्ट करतो आणि 15 मिनिटांचे सत्र जारी करतो. जारी करण्याच्या कॉलमध्ये, त्या व्यक्तीसाठी उपलब्ध असलेले MCP सर्व्हर समाविष्ट केले जाऊ शकतात. ब्राउझरला विजेटचा JWT आणि संदर्भ मिळतो.

2. वातावरण आणि जबाबदाऱ्या

प्लॅटफॉर्म https://support-ai.pontes.uk वर आहे. योग्य वातावरणाचे एकत्रीकरण क्रेडेन्शियल वापरा. वर्कस्पेस प्रशासक पॅनेलमध्ये क्रेडेन्शियल मिळवतो. ॲप्लिकेशन टीम प्रमाणीकृत बूटस्ट्रॅप, संदर्भ आणि प्रति वापरकर्ता आणि सर्व्हरसाठी प्रतिनिधी टोकन राखते.

3. क्रेडेन्शियल्स

क्रेडेन्शियल गंतव्यस्थान वापर
एकत्रीकरण क्रेडेन्शियल sik_ Support AI बॅकएंडमध्ये सत्र जारी करा
प्रति सर्व्हर प्रतिनिधी टोकन सत्रात दर्शविलेले MCP प्रमाणीकृत व्यक्ती म्हणून साधने कॉल करा
सत्राचे JWT चॅटचे API विजेटमध्ये संभाषणे उघडा आणि सुरू ठेवा

ॲप्लिकेशनच्या व्हॉल्टमध्ये एकत्रीकरण क्रेडेन्शियल साठवा. ते रद्द केल्याने पुढील विनंतीवर त्यासह जारी केलेले JWTs निष्क्रिय होतात. बॅकएंडमध्ये प्रतिनिधी टोकन तयार करा आणि प्रत्येक टोकनला एक संसाधन, वापरकर्ता आणि वैधता कालावधीपर्यंत मर्यादित करा.

4. प्रमाणीकरण आणि ओळख प्रवाह

ॲप्लिकेशनचे प्रमाणीकृत सत्र
  → बॅकएंड सक्रिय व्यक्ती, संस्था आणि वर्तमान परवानग्या सत्यापित करतो
  → सर्व्हरवर POST /api/widget/sessions सह sik_
  ← jwt + tenantKey + expiresIn
  → बॅकएंड समान ओळखीचा संदर्भ गोळा करतो आणि प्रोजेक्ट करतो
  ← ब्राउझरला Cache-Control: no-store सह सत्र/संदर्भ मिळतो
  → विजेट तात्पुरत्या JWT सह /api/cases आणि संभाषणाचे मार्ग कॉल करतो

ग्राहकाचा ऐतिहासिक ओळखकर्ता usr_... जतन केल्याने स्वतःच्या संभाषणांमध्ये प्रवेश गमावणे टाळता येते. email, भूमिका, डिव्हाइस किंवा टाइमस्टॅम्प ओळख म्हणून वापरू नका. जर समान वापरकर्ता कंपनी बदलू शकत असेल, तर बंधन किंवा स्पष्ट इतिहास धोरणाद्वारे स्थिर विषय परिभाषित करा; प्लॅटफॉर्म ग्राहक संस्थांचा अंदाज न लावता, भाडेकरू + व्यक्तीनुसार संभाषणांना अधिकृत करतो.

प्लॅटफॉर्म स्वाक्षरी, जारीकर्ता ai-support, प्रेक्षक ai-support-widget, उद्देश widget, sub=userId, वैधता आणि सत्राचे सक्रिय क्रेडेन्शियल तपासतो. ब्राउझर पुन्हा स्वाक्षरी करत नाही किंवा दावे बदलत नाही. समर्थनासाठी पाठवलेल्या भूमिका संदर्भ माहिती आहेत; APIs/MCP चे प्रमाणीकरण क्लायंट सर्व्हरवर सुरू राहते.

5. जारीकर्ता करार

POST https://support-ai.pontes.uk/api/widget/sessions
Authorization: Bearer <SUPPORT_INTEGRATION_CREDENTIAL>
Content-Type: application/json

{"userId":"usr_usuario_autenticado","userEmail":"","userRoles":["member"],"plan":"standard"}

200 प्रतिसाद: {"jwt":"<JWT>","tenantKey":"ten_do_projeto","expiresIn":900}. ब्राउझरला परत देण्यापूर्वी tenantKey सत्यापित करा. backend-session.mjs फाइल कठोर मुख्य भाग, टाइमआउट, रीडायरेक्टचे अवरोधन, प्रतिसाद मर्यादा आणि भाडेकरूचे प्रमाणीकरण लागू करते; ते तुमच्या प्रमाणीकरण मिडलवेअरची जागा घेत नाही.

फील्ड नियम
mcpServers id, url आणि अनन्य accessToken सह आठ वस्तूंपर्यंतची पर्यायी सूची. विभाग 12 पहा.
userId अनिवार्य, ट्रिम, 1–200 वर्ण
userEmail 254 वर्णांपर्यंत वैध ईमेल किंवा रिक्त; डीफॉल्ट रिक्त
userRoles 1–80 वर्णांच्या 30 स्ट्रिंगपर्यंत; डीफॉल्ट रिक्त सूची
plan 1–80 वर्णांची स्ट्रिंग; डीफॉल्ट standard

tenantId, tenantKey, userName, भूमिका, purpose, exp किंवा इतर फील्ड बॉडीमध्ये पाठवू नका. क्रेडेंशियल टेनंट निश्चित करते. ओळख सेशन/डेटाबेसवरून येते, ब्राउझरच्या क्वेरी/बॉडीवरून नाही. जारीकर्ता sik_ ऐवजी वापरकर्त्याचे JWT, प्रशासकीय की किंवा जुने रहस्य स्वीकारत नाही.

सार्वजनिक जारीकर्ता प्रति प्रकल्प वापर कोटाशिवाय कार्य करतो. त्याच व्यक्ती, कंपनी आणि परवानग्यांचे अद्याप वैध असलेले सेशन पुन्हा वापरा, लवकर मुदतवाढ आणि बदलांवर अवैधता.

6. अनिवार्य संदर्भ आणि योग्य ओळख

प्रत्येक नवीन केससाठी context.userState, context.userHistory आणि context.userLogs आवश्यक आहे. जेव्हा स्त्रोताची चौकशी केली जाते आणि कोणतेही रेकॉर्ड नसतात तेव्हा रिकाम्या सूची पाठवा; यशस्वी दिसणाऱ्या रिकाम्या सूचीमध्ये अयशस्वी झालेले संकलन रूपांतरित करू नका. जर तुम्ही वैध आणि अधिकृत संदर्भ प्रदान करू शकत नसाल, तर क्लायंट बूटस्ट्रॅपमध्ये नियंत्रित त्रुटी परत आली पाहिजे.

context.example.json हे किमान उदाहरण आहे. context.schema.json हे सर्व्हरवर वापरलेल्या Zod स्कीमामधून निर्यात केले गेले आहे, स्वतंत्रपणे लिहिलेले नाही. डिप्लॉय करण्यापूर्वी बॅकएंडवर JSON प्रमाणित करा. ओळख नसलेली अतिरिक्त फील्ड टाकून दिली जातात; मेटाडेटा आणि नियमांमध्ये स्वतःच्या संरचना असू शकतात, ज्या प्रोजेक्शन/मर्यादांच्या अधीन आहेत. स्कीमा अधिकृतता सिद्ध करत नाही किंवा सर्व संवेदनशील डेटा काढून टाकत नाही.

ब्लॉक अनिवार्य / रचना
userState userId, tenantId, roles, plan, featuresEnabled, entities, activeErrors, limitsReached
userHistory windowHours 720 पर्यंत सकारात्मक, events; टाइमलाइन events मधून पुन्हा तयार केली जाते
userLogs recentRequests, jobs, errors
knowledgePack ऐच्छिक; docs सह id, title, content, category
businessRules ऐच्छिक; मंजूर नियम ऑब्जेक्ट, रनबुक म्हणून सिरीयल केलेला

userState.userId ही जारी केलेली ओळख असावी. userState.tenantId हा प्लॅटफॉर्मचा टेनंट आहे, क्लायंटमधील संस्था/स्टोअर आयडी कधीही नाही. विसंगती 403 परत करतात. ब्राउझरमधील डेटा बदलला जाऊ शकतो; संदर्भ ऑपरेशन्सना अधिकृत करत नाही.

7. फील्ड, मर्यादा आणि सामान्यीकरण

रचना मुख्य फील्ड / नियम
entities type, status; id/description ऐच्छिक; metadata ऑब्जेक्ट; 100 पर्यंत
activeErrors errorCode, errorClass, retryable, userActionable, resourceId, occurredAt; 100 पर्यंत
activeErrors चा errorClass validation, permission, infra किंवा business; payment सारख्या श्रेणींना मॅपिंग आवश्यक आहे
events ts, event, page; elementId, intent, correlationRequestId null/वगळणे स्वीकारतात; 1,000 पर्यंत
recentRequests ts, route, httpStatus पूर्णांक, timingMs, requestId; errorCode/resourceId null असू शकतात
jobs jobId, queue, status, createdAt, updatedAt, durationMs संख्या किंवा null; errorCode/lastStage null असू शकतात
jobs चा status queued, running, succeeded, failed, canceled
बॅकएंडमधील errors ts, errorCode, errorClass स्ट्रिंग, route, requestId; resourceId null असू शकते
docs 50 पर्यंत; content 32,000 वर्णांपर्यंत, इतर मजकूर 4,096 पर्यंत

तारीखा ISO-8601 टाइमझोनसह स्ट्रिंग आहेत; बॅकएंडमध्ये तारीख सिरीयल करा. केवळ स्कीमा पास करण्यासाठी updatedAt, durationMs, retryable किंवा श्रेणी तयार करू नका: वास्तविक स्त्रोत वापरा किंवा रेकॉर्ड वगळा आणि स्त्रोताची अनुपलब्धता कळवा. तुमच्या प्रकल्पाचे विशिष्ट मॅपिंग स्वीकृतीमध्ये नोंदवा.

पाठवलेल्या संदर्भाची मर्यादा: 262.144 बाइट्स UTF-8 (256 KiB). पूर्ण HTTP 1.048.576 बाइट्सपर्यंत मर्यादित राहते. स्नॅपशॉटचे बजेट min(maxContextBytes, 262144) आहे. जर आवश्यक भागही बसला नाही, तर विनंती अयशस्वी होते; बॅकएंडमधील मेटाडेटा/दस्तऐवज कमी करा. आम्ही 48 KiB, दहा संस्था आणि कमी ज्ञानाने सुरुवात करण्याची शिफारस करतो.

सर्व्हर विनंती केलेल्या आणि टेनंटच्या सर्वात लहान विंडोनुसार इव्हेंट्स/लॉग्स फिल्टर करतो, भविष्यातील तारखा काढून टाकतो आणि विनंत्या, त्रुटी आणि jobs (या क्रमाने) एकत्रित maxLogLines लागू करतो. maxDocs सूची docs मर्यादित करते; businessRules एक स्वतंत्र रनबुक आहे आणि ते एकूण बजेट देखील वापरते. टाइमलाइन ठेवलेल्या इव्हेंट्सचे अनुसरण करते. कमी संबंधित डेटा सहसा चांगले निदान आणि कमी खर्च देतो.

8. गोपनीयता आणि सातत्य

डेटा पाठवण्यापूर्वी त्याची रचना करा: कधीही हेडर्स, कुकीज, JWTs, क्रेडेन्शियल्स, कनेक्शन स्ट्रिंग्स, स्वाक्षरी केलेले URLs, बायनरी सामग्री, इतर वापरकर्त्यांचा डेटा किंवा कच्ची निर्यात फॉरवर्ड करू नका. संदर्भांसाठी गुप्त गोष्टी बदला. संपूर्ण PRD किंवा संपूर्ण लॉग्स ज्ञानाचा आधार म्हणून पाठवू नका.

नवीन स्नॅपशॉट्स रेकॉर्डिंग करण्यापूर्वी प्रमाणीकरण, संपादन, कमी करणे आणि बजेटमधून जातात. संदेश आणि साधनांच्या परिणामांवर ज्ञात गुप्त नमुन्यांनुसार प्रक्रिया केली जाते. हे संरक्षण पूरक आहे: हे वैयक्तिक डेटाचे अचूक वर्गीकरण करणारे नाही, ऐतिहासिक नोंदी पूर्वलक्षी प्रभावाने दुरुस्त करत नाही किंवा ग्राहकांच्या डिझाइनची जागा घेत नाही.

संदर्भ म्हणजे संभाषणाच्या सुरुवातीचा स्नॅपशॉट, रिअल-टाइम क्वेरी नाही. टाइमस्टॅम्प आणि स्रोत कळवा. updateContext() पुढील केससाठी लागू होते; संभाषणादरम्यानच्या सध्याच्या डेटासाठी, मंजूर वाचन साधन वापरा.

9. फ्रंटएंड आणि SDK 0.3.0

पॅकेजमधून किंवा सार्वजनिक URL वरून निश्चित SDK सर्व्ह करा. widget.manifest.json सह SHA-256 तपासा. डुप्लिकेट स्क्रिप्ट, फ्लोटिंग आवृत्ती आणि JWT कॅशे टाळा. widget-controller.mjs मधील संदर्भ नियंत्रक बूटस्ट्रॅप नंतर माउंट करतो, onOpen ची वाट पाहतो, नूतनीकरण करतो आणि लॉगआउट नंतर उशीरा माउंटिंग प्रतिबंधित करतो.

const controller = mountSupport({
  apiUrl: 'https://support-ai.pontes.uk',
  bootstrap: signal => fetchAuthenticatedBootstrap(signal),
  getContext: signal => fetchAuthorizedContext(signal),
  onUnavailable: () => showHumanSupportChannel(),
});
// लॉगआउटवर, व्यक्ती/कंपनी/भूमिका बदलल्यावर आणि घटक साफ केल्यावर:
controller.destroy();

वरील फंक्शन्स ॲप्लिकेशनचे कॉलबॅक आहेत, जे तुमच्या नेहमीच्या HTTP क्लायंटसह लागू करायचे आहेत. बूटस्ट्रॅप {jwt,tenantKey,expiresIn,context} परत करतो. getContext संदर्भ ऑब्जेक्ट परत करतो. React मध्ये, useCallback सह कॉलबॅक स्थिर करा आणि ओळखेशी जोडलेल्या useEffect मध्ये माउंट करा. विजेटला प्रमाणीकृत क्षेत्राबाहेर ठेवू नका किंवा सामायिक userId सह अभ्यागतांना देऊ नका.

  4. एकाच प्रकल्पातील दोन व्यक्ती आणि दोन भाडेकरू: GET केस आणि POST संदेश/फीडबॅक/बंद/एस्केलेट/क्रिया ओळख ओलांडत नाहीत.

16. प्रकाशन, कटऑफ आणि पुनर्प्राप्ती

एकात्मिक क्रेडेन्शियल स्थापित करा, बूटस्ट्रॅप आणि SDK प्रकाशित करा, चॅटची पडताळणी करा आणि सत्रांमध्ये घोषित सर्व्हरना मान्यता द्या.

उपलब्धता पुनर्प्राप्त करण्यासाठी जुन्या सदस्यत्वे किंवा जागतिक MCP फॉरवर्डिंग पुन्हा सक्रिय करू नका. जर अयशस्वी झाले, तर प्रभावित टेनंटचे विजेट किंवा MCP तात्पुरते अक्षम करा आणि अडॅप्टर दुरुस्त करताना मानवी चॅनल चालू ठेवा. मालकाच्या 404 ला बायपास करण्यासाठी संभाषणे हटवू नका.

धारण मर्यादा आणि आपल्या ॲप्लिकेशनचे विशिष्ट पुरावे नोंदवा.

17. फीडबॅक आणि पॅकेज फाइल्स

प्रकल्पाचे नाव, टेनंट, बॅकएंड/फ्रंटएंड कमिट्स, UTC तारीख, SDK/हॅश, स्थापित क्रेडेन्शियल (होय/नाही, मूल्य नाही), मंजूर चॅट, MCP मंजूर/बंद, नकारात्मक चाचण्या, मानवी चॅनल आणि प्रलंबित बाबी परत करा. “काम करत असल्याचे दिसते” असे म्हणून निष्कर्ष काढू नका.
